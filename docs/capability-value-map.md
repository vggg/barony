# Barony — capability → value → metric

Companion to [product-overview.md](product-overview.md). One row per capability: what it
delivers, the metric that moves if it works, and — the column that matters most — how that
metric is actually obtained and whether anyone has obtained it yet.

**Read the status column first.** Barony has zero external adopters. Every number below is
either first-party, from Barony's own pilot fleets, or has not been measured at all. A table
of metrics with no honesty column is a roadmap wearing a lab coat.

| Status | Meaning |
|---|---|
| **proven** | Measured, first-party, on a real project, and the number is recorded in this repo or an ADR. |
| **instrumented** | The mechanism emits the data. Nobody has run it long enough on enough projects to report a number. |
| **aspirational** | The metric is defined and the capability is designed for it. No instrumentation, no number. |

## 1. The merge gate and review integrity

| Capability | Value delivered | Metric it moves | How measured | Status |
|---|---|---|---|---|
| **Deterministic merge gate** — `baron merge check` ([ADR-028](adr/ADR-028-mechanized-merge-gate.md)) | A merge decision becomes a fail-closed return value instead of prose the model can talk itself past. Stale and unreviewed merges are refused, not discussed. | **Reviewer escape rate** — merges whose verdict did not name the merged head sha, over all merges. Secondary: refusals by reason slug (`stale_verdict`, `ci_pending`, `no_verdict`). | Re-run the gate's four preconditions over a repo's merge history from the forge API + git. The gate itself emits a stable reason slug per refusal, so the denominator and the breakdown come from the same source. | **instrumented** — the gate ships and refuses; no escape-rate series exists yet. The pilot's pre-gate counter-evidence is FM4 (~15 merges under a denied `merge_pr`). |
| **Signed review verdicts** ([ADR-033](adr/ADR-033-signed-review-verdicts.md)) | Separation of duties stops being a claim in a persona file. Reviewer ≠ author becomes a property of the repo, checkable offline by a stranger with a bare clone. | **Claim integrity** — share of merged PRs carrying a verdict whose signature verifies, binds (repo, PR, sha), comes from a reviewer-archetype signer, and whose signer ≠ the head commit's signing principal. The complement is the number that creates the pain. | `baron review verify` over the history, or `ssh-keygen -Y verify` against in-repo `.barony/allowed_signers` with no Barony installed. All four legs are independently checkable; an unresolvable author is fail-closed as `verdict_author_unresolved`. | **instrumented** — four legs implemented and tested; no cross-repo rate published. |
| **Agent identity** — per-persona SSH keys ([ADR-027](adr/ADR-027-agent-identity.md)) | Provable authorship. An artifact's author is a key enrolled by a human merge, not a self-asserted string — so "who wrote this" survives leaving the forge. | **Attribution coverage** — commits in `BASE..HEAD` passing signature + trust-status `G` + the three-way cross-check. And **owner-correction rate**: misattributions the owner has to fix by hand. | `baron verify identity` as a required status check; coverage is its pass count over commit count. Correction rate is a manual count of owner-authored corrections — genuinely hand-tallied, and labelled as such. | **proven for the mechanism, aspirational for the rate.** The failure it fixes is measured and dated: 2026-08-04, one Codex commit to `main` under the owner's identity, unattributable from the repo. |
| **Identity onboarding** — `baron identity register\|enroll\|protect` | The runbook stops being a checklist that gets half-done on persona seven, without moving the trust boundary: `enroll` opens the request and stops. | **Onboarding completion rate** — personas fully enrolled (key registered, allowed-signers merged, ruleset on) over personas spawned. | `baron identity show` lists who is enrolled in this repo; the denominator is `agents/*/persona.yaml`. Both sides read from the repo. | **instrumented** — commands ship, dry-run by default; no fleet-wide series. |

## 2. Capability boundaries

| Capability | Value delivered | Metric it moves | How measured | Status |
|---|---|---|---|---|
| **Capability enforcement** — `baron guard` ([ADR-004](adr/ADR-004-baron-guard-enforcement.md)) | A denied capability cannot be exercised through the governed seam. The rule and the control stop being the same word. | **Capability-bypass rate** — denied-verb operations that nevertheless completed, over denied-verb attempts. Secondary: **override rate** (`BARON_GUARD_OVERRIDE` uses, which are tracked in git by design and expected to become handoffs). | Guard emits a row per adjudicated call on the observation plane; overrides append to a tracked log, so both numerator and denominator are in the repo. **Two things are out of the denominator by construction, and neither is a rounding choice.** (1) A `bash -c` payload past ADR-034's one-level recursion — or an untokenisable one, or `python -c`/`eval`/base64 indirection — is never adjudicated, so it can never be counted as a bypass; v1.20.0 *narrows* that class, it does not close it. (2) A `BARON_GUARD_OVERRIDE` use is an allow-and-log, not a bypass, and is counted in the override rate instead — which is why that secondary metric is load-bearing rather than cosmetic. | **proven for a denial, aspirational for the rate.** A live guard refusal is captured in the demo repo; no bypass-rate series exists. An opt-in tier ([ADR-034](adr/ADR-034-deterministic-capability-enforcement.md)) now drives a real runtime and asserts the denied operation *did not run* — the first evidence about the world rather than about wiring — but it is **advisory, gates nothing, and has not been run**. |
| **Structural policy immutability** — `baron guard` L0 ([ADR-034](adr/ADR-034-deterministic-capability-enforcement.md)) | The enforced party can no longer rewrite the policy that governs it. A persona cannot edit any `persona.yaml`, its own `agents/<slug>/` dir, `.claude/settings.json{,.local}`, `.baron-waivers.yaml`, `.baron-rules.yaml` or `.barony/allowed_signers` — so **changing a capability set becomes a PR a human merges, always, including for a solo owner**. Every layer above this one was conditional on it. | **Self-amendment rate** — capability-set changes that landed without a human-merged PR, over capability-set changes. Target zero, and unlike a rate over attempts this one is *complete*: every grant lives in a tracked file, so the denominator is the git history of `agents/*/persona.yaml`. Secondary: **L0 refusal count**, which is a leading indicator of agents trying. | Diff every commit touching a fenced path against the PR that merged it — both sides are in the repo, checkable offline with no Barony installed. L0 refusals arrive on the observation plane labelled `unevaluated` (no capability decided them), so they are countable but deliberately *not* mixed into the enforced-denial series. | **proven as a refusal, aspirational as a rate.** Pinned by `cli/tests/test_guard_l0.py` — including the two G5 attacks end-to-end through the real hook, and the trailing match under a non-acting persona's slug. No self-amendment series exists. **Bound: `BARON_GUARD_OVERRIDE` reaches L0 too** — it is applied after the decision, so a shell can wave a structural refusal through. It is out of the numerator and logged to a tracked file, which is the trade: recorded, not prevented. |
| **Enforcement wiring self-test** — `baron doctor` ([ADR-017](adr/ADR-017-baron-doctor-wiring-selftest.md)) | The FM4 residual: silent absence. An unwired guard and a guard that never fired stop leaving identical evidence. | **Wiring compliance** — working copies passing all ten checks over working copies expected to enforce. | `baron doctor --json` per working copy; ten read-only checks, exit 1 on any FAIL with a remedy line. The tenth (`platform-layer`, ADR-034 L3) is **INFO and never FAIL** — it reports branch protection and per-persona push credentials rather than gating on them, and its networked half is opt-in behind `BARON_DOCTOR_PLATFORM=1`. | **proven as a check, instrumented as a rate.** **Bound the metric inherits:** doctor verifies *wiring, not invocation* — 100% compliance does not mean enforcement happened. |
| **The honesty ladder** — enforced vs instructed, `baron rules list` ([ADR-016](adr/ADR-016-externalizable-capability-rules.md), [ADR-020](adr/ADR-020-read-verb-posture-measured-on-four-adapters.md)) | Nobody buys a control that turns out to be a sentence. Claims are machine-checked against what baron actually emits. | **Over-claim count** — capability rows claiming enforcement the adapter cannot deliver. Target is zero, enforced in CI. | `tests/bi_runtime_accept.py` parses every adapter's machine-readable capability map and fails the build on an unsupported claim. | **proven, and it has fired.** The read verbs moved `enforced` → `instructed` on measurement across four adapters — baron now reports *less* enforcement than it used to. That correction is the metric working. |

## 3. Decision durability and knowledge

| Capability | Value delivered | Metric it moves | How measured | Status |
|---|---|---|---|---|
| **Prior-art gate** — `baron adr check` ([ADR-029](adr/ADR-029-prior-art-gate.md)) | Stops re-derivation. A decision cannot be accepted without a recorded sweep of the corpora that would have contained the answer. | **Re-derivation rate** — accepted ADRs that duplicate prior art, over accepted ADRs. | Count supersession relationships that were discovered *after* acceptance rather than cited in the sweep. The ADR index records these in both directions, so the count is auditable from the repo. | **proven — as a first-party failure case.** ADR-011 and ADR-027 are the same design, from the same 2026-08-04 spike, re-derived ten days apart with neither citing the other. That is the numerator's first entry, recorded rather than quietly dropped. The gate exists to make the second one harder. |
| **`baron export`** ([ADR-015](adr/ADR-015-baron-export.md), [ADR-032](adr/ADR-032-export-reach-monorepo-and-widened-corpus.md)) | The governed corpus becomes citable records that reproduce byte-for-byte. Any downstream projection inherits auditability from the walk rather than earning it per backend. | **Citation fidelity** — records whose cited commit+path reproduce the parsed bytes exactly. Secondary: **corpus coverage** (records emitted over source documents present). | `git show <sha>:<path>` per record, compared byte-for-byte. Untracked or modified sources are skipped **and named**, so coverage loss is visible rather than silent. | **proven** — 284 records from a real pilot repo, **all 284 citations verified by byte-equality**. Coverage is the honest weak spot: ADR-032 exists because a root-level walk had been returning a silent zero. |
| **Decision reconciliation** ([ADR-009](adr/ADR-009-baron-decision-reconciliation.md)) | FM6: a ratified decision reaches the work-pull surfaces instead of leaving a closed question generating work. | **Decision-to-surface latency** — time from ratification to the backlog/handoff reflecting it. Secondary: open obligations past SLA. | Ledger timestamps vs. the diff that updated the work surfaces. | **aspirational** — ADR-009 is *proposed / parked*, design only, no code on the main line. Listed because the failure is measured (D56/D57 on the pilot) even though the mechanism is not built. |

## 4. Fleet operation

| Capability | Value delivered | Metric it moves | How measured | Status |
|---|---|---|---|---|
| **Fleet health** — `baron health` ([ADR-024](adr/ADR-024-fleet-health.md)) | Whether the fleet's *defences* are strong, not whether it is busy. Test suites that kill mutants, reviewers that catch what they should, work that is not stuck. | **Mutation-kill rate**, **claim drift** (with direction — understating counted separately), **reviewer escape rate**, **stall count**. | Verdict metrics arrive as `review.verdict` events on the observation plane; the stall half is computed by `baron status` from git and handoff state. | **proven on the pilot, instrumented in the product.** The numbers ran on the pilot's private runner; ADR-024 moved them onto the substrate so an adopter gets them from a clone. **Bound the metric inherits (ADR-024 §5): it measures what was emitted.** A reviewer that runs no mutations reports no kill rate — an absence of evidence, not a clean bill. |
| **The observer archetype** ([ADR-030](adr/ADR-030-observer-archetype.md)) | Somebody is watching. The substrate emits more than anyone reads, and drift or void-production is caught while it is cheap. | **Time-to-detect** — from the first emitted signal of a drift/stall/void-production condition to it appearing in `observations/` or a raised handoff. | Timestamp of the earliest qualifying event on the plane vs. the observation note's commit time. Both are in git. | **aspirational** — ADR-030 is *proposed*; owner gates. No observer has run. |
| **Read-only audit / intervention tax** (`skills/multi-agent-audit/`) | Grades any multi-agent project, framework-neutral, with evidence instead of vibes. A high autonomy split with a high tax is a false win. | **Intervention tax** — human touches per autonomous task. **Operational fidelity** — declared protocol vs. observed behaviour, 0.00–1.00. | Read-only git and artifact archaeology; the dual-lens drift pass compares declaration against practice. | **proven, first-party only.** A real multi-agent project measured **0.53 operational fidelity** — roughly half the documented protocol actually followed — and the number was published rather than rounded up. **No non-first-party number exists**, which is the single most valuable artifact the audit could still mint. |
| **`baron notify` wake** ([ADR-010](adr/ADR-010-baron-notify-wake.md)) | FM1: a human stops being the message bus. A cold headless agent is woken by a platform event instead of a wall-clock poll. | **Handoff pickup latency** — from a handoff landing to the addressed persona acting. Secondary: **empty-sweep rate**, spawns that found no work. | Handoff `created` timestamp vs. first commit by that persona referencing it — both in git. Empty sweeps are countable from the dispatch log. | **aspirational** — the pilot's baseline is a 15-minute cron that spawns whether or not there is work. No latency series has been collected. |
| **Coordination monorepo** ([ADR-025](adr/ADR-025-coordination-monorepo.md)) | One clone answers "what is my whole fleet doing, and what needs me across all of it?" — instead of 2N repos and no cross-project view. | **Cross-project visibility** — projects covered by a single `baron status` / `baron health` run. Secondary: **portfolio red count**. | Portfolio-wide walk of the subdirs; the rollup is the measurement. | **proven mechanically, aspirational as an outcome.** The rollup works and is dogfooded. **Cost, stated:** access is all-or-nothing — a monorepo cannot grant per-project access — so this is a mode, not a replacement. |
| **Persona sidecar** ([ADR-026](adr/ADR-026-persona-sidecar.md)) | A persona becomes a reproducible deployable rather than a hand-written launcher on the author's laptop. | **Deployment reproducibility** — personas brought online from the emitted launcher with no hand-editing, over personas deployed. | Count of emitted `sidecar.sh` runs that reach a first pushed unit of work unmodified. | **aspirational** — the launcher form ships and `--dry-run` works; the container form is deliberately later, and nobody has run a fleet this way outside the author's machine. |
| **Observation plane** ([ADR-013](adr/ADR-013-observation-plane-events-and-sinks.md), [ADR-018](adr/ADR-018-adjudicated-enforcement-on-the-event.md), [ADR-019](adr/ADR-019-runtime-neutral-event-plane.md)) | One event vocabulary every other metric on this page is computed from — runtime-neutral, opt-in, and honest about what a row can claim. | **Enforcement-observation accuracy** — rows whose `enforced` / `unevaluated` / `unknown` label matches whether a capability actually adjudicated that call. **Runtime neutrality** — attributes that differ between two runtimes driven identically. | The label is read off an explicit flag defaulting to `False` at every return site, so an unadjudicated path is `unevaluated` by construction rather than by someone remembering. Neutrality is measured by driving two runtimes with the same persona and diffing the rows. | **proven** — two producers write the same plane and differ in **exactly four** attributes (`baron.runtime`, `baron.trigger`, `tool.name`, `session.id`); verdict, verb, enforcement label, actor and subject are identical. That falsifies "the plane is one runtime's shape" — it is not proof the shape fits every runtime. **Consumer caveat:** the verb tuple is not a proxy for the enforcement field; filter on `enforcement == "enforced"` *before* grouping by verb, or the count is fiction. |

## 5. What none of these metrics can tell you

Four limits that apply across the whole table, so a reader does not have to reconstruct them
row by row.

1. **Every number here is first-party.** Barony's own pilots and audits produced all of it.
   No external team has run any of these measurements, and until one does, the strongest
   claim available is "measured, on our own work, and published including the bad numbers."
2. **Absence reads as health, everywhere.** `baron health` measures what was emitted; guard's
   bypass class is outside its own denominator; doctor proves wiring, not invocation. A green
   dashboard built from these metrics is consistent with nothing having run at all — which is
   why the surfaces report `UNATTRIBUTED` and "not evaluated — fail-closed" rather than
   rendering a gap as a pass.
3. **The enforcement metrics describe cooperating agents.** They quantify honest mistakes
   caught, not attacks repelled. A hostile actor with write access to an agent's workspace
   holds that agent's signing key and can defeat the attribution metrics outright.
4. **A metric computed from a governed substrate flatters the governed.** These numbers are
   derived from artifacts that only exist when the process was followed at least partly. The
   audit's operational-fidelity pass is the deliberate counterweight — it is the one
   measurement designed to say *the protocol was not followed*, and it is the reason the
   headline first-party number is 0.53 rather than something more comfortable.
