Barony

Git-native governance for teams of AI coding agents

Barony proves that agent-written code was reviewed by something other than the thing that wrote it — as signed artifacts in your own repo, checkable offline, on any forge.

The git repo is the only source of truth; anything hosted is a rebuildable cache. A control plane cannot attest to itself — so the evidence lives where you can still read it after the vendor, the forge and the dashboard are all gone.

How the data gets here

The coordination repository is private and stays private. dashboard/build-data.sh runs the read-only baron reporters against it and writes a one-way, sanitised projection to dashboard/data/fleet.json — the only thing published. Absolute paths, record bodies and handoff contents never leave.

Metrics are reported honestly: anything with an empty denominator renders as n/a with its basis rather than a flattering 0% or 100%, and single-observation figures are labelled n=1. Unmerged capabilities are shown as not active, not as passing.

The two document pages are a different pipeline with the same rule — no hand-entered content. dashboard/build-docs.sh renders them from docs/product-overview.md and docs/capability-value-map.md, and CI fails if a page has drifted from its markdown source.
